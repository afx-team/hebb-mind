# 开源项目分析

在设计 Hippocampus 之前，我们深入分析了主流的开源 Agent 记忆项目，总结其优缺点和对本项目的启发。

## Mem0

**仓库**: [mem0ai/mem0](https://github.com/mem0ai/mem0)

**定位**: 面向 AI 应用的记忆层。

**架构特点**:
- 基于向量数据库的记忆存储
- 支持多种向量库（Qdrant、Pinecone、ChromaDB 等）
- 通过 LLM 提取和更新记忆
- 提供 Python SDK 和 REST API

**优点**:
- 接口简洁，易于集成
- 社区活跃，生态丰富
- 支持多种向量数据库

**不足**:
- 无记忆分区概念，所有记忆混在一起
- 无遗忘机制，记忆只增不减
- 无知识图谱
- 检索只依赖向量相似度

## Letta (原 MemGPT)

**仓库**: [letta-ai/letta](https://github.com/letta-ai/letta)

**定位**: Agent 驱动的记忆管理框架。

**架构特点**:
- Agent 通过函数调用管理记忆
- 主记忆 + 归档记忆两层结构
- 完整的 Agent Server 实现
- 支持多用户和多 Agent

**优点**:
- Agent 自主管理的设计理念先进
- 两层记忆结构比单一存储更灵活
- 支持对话状态管理

**不足**:
- 架构复杂，部署门槛较高
- 只有两层记忆分类，颗粒度不够
- 无遗忘机制
- 无知识图谱

## Zep

**仓库**: [getzep/zep](https://github.com/getzep/zep)

**定位**: 长期记忆服务，强调知识图谱。

**架构特点**:
- 基于 Neo4j 的时序知识图谱（Graphiti）
- 自动从对话中提取实体和关系
- 向量搜索 + 图谱搜索混合检索
- 支持时间感知的查询

**优点**:
- 知识图谱能力强大
- 时序感知是独特优势
- 实体关系提取质量较高

**不足**:
- 依赖 Neo4j，部署较重
- 无明确的记忆分区
- 遗忘只有隐式实现
- 闭源组件较多

## 综合对比

| 特性 | Mem0 | Letta | Zep | **Hippocampus** |
|------|------|-------|-----|-----------------|
| 记忆分区 | 无 | 两层 | 无 | 五分区 + 自定义 |
| 记忆巩固 | LLM 提取 | Agent 函数 | 图谱构建 | 巩固代理 |
| 遗忘机制 | 无 | 无 | 隐式 | 动态 TTL |
| 知识图谱 | 无 | 无 | Neo4j | NetworkX |
| 向量检索 | 是 | 是 | 是 | 是 |
| 关键词检索 | 无 | 无 | 无 | FTS5/tsvector |
| 零配置部署 | 需向量库 | 较复杂 | 需 Neo4j | SQLite 即可 |
| 多模型支持 | 部分 | 部分 | 部分 | LiteLLM 全覆盖 |
| Web 管理界面 | 无 | 有 | 有 | 有 |

## 对 Hippocampus 的启发

通过分析这些项目，我们确定了 Hippocampus 的差异化方向：

1. **仿脑分区** — 不是简单的两层或单层存储，而是参照认知科学的记忆分类
2. **主动遗忘** — 引入动态 TTL 机制，让记忆系统保持健康
3. **零配置起步** — 使用 SQLite 作为默认后端，降低入门门槛
4. **三路混合检索** — 向量 + 关键词 + 图谱并行，提高召回质量
5. **轻量知识图谱** — 使用 NetworkX 而非 Neo4j，避免重度依赖
