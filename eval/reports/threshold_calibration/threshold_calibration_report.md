# Strict-Recall 阈值校准评审报告（V2 — 全量数据）

**日期**: 2026-07-30
**Issue**: #31 — feat(retrieval): make the strict-recall score floor configurable + recalibrate for the cross-encoder scale
**审计项**: C5 / 召回F3
**数据规模**: LoCoMo 全量 1978 道查询，19766 条结果

---

## 1. 结论先行

**核心结论：sigmoid 分数不适用于硬过滤，问题的本质不是"阈值调多少"，而是"用错了过滤维度"。**

具体来说：

1. **bge-reranker-base 的 sigmoid 分数分布严重左偏**，相关样本中位数仅 0.166（推导假设"~0.5"完全不成立），用 sigmoid 做门槛无论怎么调 ratio 都无法同时满足 R@10 ≥ 90% 和空召回率 < 5%。
2. **当前默认配置 (0.8, 0.625) 严重不可用**：39% 的查询返回空集，R@10 仅 53.5%。
3. **正确方案是"reranker 负责排序，composite 分负责过滤"**：保留 reranker 的排序增益（R@10 从 91.5% 提升到 94.6%），但门槛只卡 composite 分。
4. **推荐默认值 `recall_min_score = 0.6`**：R@10 = 91.7%，空召回率 = 1.0%，平均返回 7.4 条——在过滤纯度与召回率之间取得最佳平衡。

---

## 2. 数据全景

### 2.1 分数分布（全量 19766 条结果）

| 分数体系                    | 数量    | 均值    | p10   | p50       | p90   | max   |
| ----------------------- | ----- | ----- | ----- | --------- | ----- | ----- |
| Composite 分（无 reranker） | 19766 | 67.5% | 42.4% | 69.4%     | 88.3% | 100%  |
| Sigmoid 分（有 reranker）   | 19766 | 18.1% | 0.2%  | **3.9%**  | 68.1% | 100%  |
| 相关样本 sigmoid            | 6348  | 33.1% | 0.7%  | **16.6%** | 93.1% | 100%  |
| 不相关样本 sigmoid           | 13418 | 11.0% | 0.2%  | 2.4%      | 36.5% | 99.9% |

**关键问题**：sigmoid 分布极度左偏。推导 0.625 ratio 时假设"相关 hit sigmoid ~0.5"，实际中位数仅 16.6%，**偏差 3 倍以上**。这意味着 `0.8 × 0.625 = 0.5` 的实际门槛，卡在了相关样本的 p90（93.1% 分位）附近——直接砍掉了 90% 以上的正确命中。

### 2.2 三模式基线对比（无任何门槛过滤）

| 模式                          | 说明         | R@1   | R@3   | R@5   | R@10      |
| --------------------------- | ---------- | ----- | ----- | ----- | --------- |
| A — 纯 composite             | 无 reranker | 68.0% | 81.9% | 86.8% | **91.5%** |
| B — reranker + sigmoid 过滤   | 当前生产逻辑     | 71.9% | 87.3% | 91.5% | **94.6%** |
| C — reranker + composite 过滤 | 推荐方案       | 71.9% | 87.3% | 91.5% | **94.6%** |

**reranker 的排序增益**：R@10 从 91.5% → 94.6%（+3.1 个百分点）。这个增益是有价值的，应当保留。

### 2.3 当前默认配置 (0.8, 0.625) 的表现

| 模式               | 实际门槛 | R@1   | R@10      | 空召回率      | 平均结果数 |
| ---------------- | ---- | ----- | --------- | --------- | ----- |
| A — composite 过滤 | 0.8  | 55.4% | 63.6%     | **27.5%** | 2.36  |
| B — sigmoid 过滤   | 0.5  | 48.8% | **53.5%** | **39.0%** | 1.44  |
| C — composite 过滤 | 0.8  | 57.1% | 64.9%     | **27.5%** | 2.26  |

**39% 的查询返回空集。这意味着近四成用户在 strict recall 模式下什么都搜不到。**

## 3. 核心发现

### 3.1 模式 B（sigmoid 过滤）：死路

全参数扫描（10 × 16 = 160 种组合），没有任何一组能同时满足 R@10 ≥ 90% 且空召回率 < 5%。

最宽松的参数组合（min_score=0.5, ratio=0.3, 实际门槛=0.15）：

| 指标    | 值         |
| ----- | --------- |
| R@10  | 71.8%     |
| 空召回率  | **19.7%** |
| 平均结果数 | 3.0       |

即便把门槛压到 0.15（几乎不过滤），仍然有 20% 的查询返回空集，R@10 也只有 72%。**这不是阈值调优能解决的问题，而是 sigmoid 分数本身不适合做硬过滤**。

原因：

- sigmoid 分 p50 = 3.9%，绝大部分结果挤在 0 附近
- 相关与不相关样本的 sigmoid 分布高度重叠（相关 p50=16.6% vs 不相关 p50=2.4%）
- 任何有意义的门槛都会同时砍掉大量正确结果

### 3.2 模式 A/C（composite 过滤）：可行

Composite 分分布健康（p50=69.4%），有良好的区分度。

**全量数据关键阈值点**：

| min_score  | A — R@10  | A — 空召回率 | C — R@10  | C — 空召回率 | C — 平均结果数 |
| ---------- | --------- | -------- | --------- | -------- | --------- |
| 无门槛        | 91.5%     | 0.0%     | 94.6%     | 0.0%     | 10.0      |
| **0.50**   | **90.4%** | **0.3%** | **93.0%** | **0.0%** | **8.7**   |
| 0.55       | 90.0%     | 0.5%     | 92.8%     | 0.1%     | 8.1       |
| **0.60**   | **89.0%** | **1.0%** | **91.7%** | **1.0%** | **7.4**   |
| 0.65       | 86.0%     | 2.7%     | 88.5%     | 2.7%     | 6.2       |
| 0.70       | 81.2%     | 6.5%     | 83.6%     | 6.2%     | 4.8       |
| 0.80（当前默认） | 63.6%     | 27.5%    | 64.9%     | 27.5%    | 2.3       |

### 3.3 Reranker 的价值

| 对比               | R@10       | 说明             |
| ---------------- | ---------- | -------------- |
| A 基线（无 reranker） | 91.5%      | 纯 composite 排序 |
| C 基线（有 reranker） | 94.6%      | reranker 改善排序  |
| 差值               | **+3.1pp** | reranker 排序增益  |

Reranker 确实提升了排序质量，但它的 sigmoid 输出分数不适合做过滤。正确做法是**让 reranker 只负责排序，门槛过滤用 composite 分**。

---

## 4. 推荐方案

### 4.1 架构决策

**门槛只卡 composite 分，reranker 仅负责排序。**

理由：

1. Composite 分分布健康（p50=69.4%），有区分度
2. Sigmoid 分严重左偏（p50=3.9%），无法做有效过滤
3. 这样既保留 reranker 的排序增益（+3.1pp R@10），又避免 sigmoid 过滤导致的空召回

### 4.2 推荐默认值

| 配置项                  | 当前值   | 推荐值            | 理由                              |
| -------------------- | ----- | -------------- | ------------------------------- |
| `recall_min_score`   | 0.8   | **0.6**        | R@10=91.7%, 空召回率=1.0%, 平均 7.4 条——平衡过滤纯度与召回率 |
| `rerank_floor_ratio` | 0.625 | **保留但不参与默认过滤** | 作为回退开关，需要 sigmoid 过滤时可启用        |

**更宽松方案（如需零空召回）**：`recall_min_score = 0.5`，R@10=93.0%，空召回率=0.0%，平均 8.7 条。

### 4.3 两种方案对比

| 指标    | 当前默认 (0.8, sigmoid) | 推荐方案 (0.6, composite) | 宽松方案 (0.5, composite) |
| ----- | ------------------- | --------------------- | --------------------- |
| R@10  | 53.5%               | **91.7%**             | 93.0%                 |
| 空召回率  | 39.0%               | **1.0%**              | 0.0%                  |
| 平均结果数 | 1.4                 | 7.3                   | 8.7                   |
| R@1   | 48.8%               | 71.9%                 | 71.9%                 |

推荐方案（0.6, composite）相比当前默认：**R@10 提升 38.2 个百分点（53.5% → 91.7%），空召回率从 39.0% 降至 1.0%。**

## 5. 工程实现建议

### 5.1 代码变更

在 `searcher.py` 的 floor 过滤循环中（第 285-292 行），对所有结果（包括 reranked pool）统一使用 composite 分（`_pre_rerank_score`）做门槛比较：

```python
# 当前逻辑：reranked pool 用 sigmoid 分做门槛
floor = rerank_floor if i < reranked_count else query.min_score

# 推荐逻辑：统一用 composite 分做门槛
floor = query.min_score  # 所有结果都用 composite 分
```

### 5.2 上线策略

- 本次变更仅调整过滤阈值和过滤维度，不改变结果的相对排序顺序
- 属于单调门槛调整，符合 Issue 中"仅调整门槛无需 A/B 测试"的发布规则
- 可直接灰度上线

### 5.3 向后兼容

- 存量调用方不传 `min_score` 时，自动使用新全局默认值 0.6
- `rerank_floor_ratio` 保留为可配置项，需要回退到 sigmoid 过滤时可一键切换

## 6. 剩余风险与后续建议

### 6.1 数据集局限性

本评测仅在 LoCoMo 上进行。建议：

1. 补充 LongMemEval 和 MemBench 数据集的验证
2. 在 MCP server 和 Claude Code hook 上做端到端体验测试

### 6.2 Reranker 模型优化

bge-reranker-base 在对话数据上 sigmoid 分数严重左偏。如果未来需要基于 reranker 分数做更多操作（如置信度展示），建议评估替换模型（bge-reranker-v2-m3、cross-encoder/ms-marco-MiniLM 等）。

### 6.3 `rerank_floor_ratio` 的定位

当前方案下 `rerank_floor_ratio` 默认不生效（因为门槛统一用 composite 分）。建议：

- 保留该配置项作为紧急回退开关
- 在文档中说明：仅在需要回退到 sigmoid 过滤逻辑时才调整此值
